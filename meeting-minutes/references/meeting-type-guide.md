# 常见会议类型处理指南

## 已覆盖类型

### 决策会 (Decision Meeting)
- **特征关键词**：方案、选择、批准、否决、决定、拍板、定下来
- **输出侧重**：决策依据 + 最终决定 + 后续执行动作
- **模板适配**：议题讨论中"结论/决议"为必填，且需包含决策理由
- **待办特征**：多为"执行决策"类待办，如"按决定修改方案"、"通知相关方"

### 同步会 (Status Sync)
- **特征关键词**：进展、进度、完成、阻塞、blocker、下周计划
- **输出侧重**：当前状态 + 下步计划 + blocker 升级
- **模板适配**：议题讨论中强调"当前状态"和"下步计划"
- **待办特征**：多为"推进/跟进"类待办，如"解决XX阻塞"、"下周三前完成XX"

### 头脑风暴 (Brainstorming)
- **特征关键词**：想法、建议、可以试试、有没有可能、探索
- **输出侧重**：想法列表 + 可行性初步判断 + 优先级排序
- **模板适配**：可在议题讨论后附加"想法汇总"或"优先级排序"表格
- **待办特征**：多为"调研/验证"类待办，如"调研XX的可行性"、"出个初步方案"

## 扩展类型（输入中可能遇到）

### 站会 (Daily Standup)
- **特征关键词**：昨天做了、今天做、受阻、需要帮助
- **输出侧重**：按人头列出三要素（昨日/今日/阻塞），而非按议题
- **模板适配**：
  - "议题讨论"替换为"成员进度"小节，按成员排列
  - 阻塞项直接并入"风险与关注项"
  - 不强制归并议题（站会天然按人组织）
- **待办特征**：来自"需要帮助/协助"的诉求
- **识别提示**：如果输入出现"昨天"、"今天"、"站会"、"daily"等词，优先判定为站会

### 评审会 (Review Meeting)
- **特征关键词**：评审、review、审批、通过/不通过、修改意见
- **输出侧重**：评审意见汇总 + 通过/有条件通过/驳回 + 修改要求清单
- **模板适配**：
  - 在"结论/决议"中明确给出评审结果（通过/修改后通过/驳回）
  - 修改意见可独立为"修改要求"小节
- **待办特征**：修改项、补充材料、重新提交
- **识别提示**：如果输入集中在对某个文档/方案/产品的逐条意见，优先判定为评审会

### 一对一沟通 (1-on-1)
- **特征关键词**：聊聊、交流、反馈、个人发展、困惑
- **输出侧重**：讨论要点 + 共识 + 后续行动（偏轻量）
- **模板适配**：
  - 参与者通常仅 2 人
  - 议题可能较松散，允许以"话题"替代"议题"
  - 可省略"风险与关注项"章节（如无实质风险）
- **待办特征**：个人层面的行动计划

### 复盘会 (Retrospective)
- **特征关键词**：复盘、回顾、做得好的、做得不好的、改进、lesson learned
- **输出侧重**：亮点 + 不足 + 改进措施（Action Items）
- **模板适配**：
  - 可在"议题讨论"前增加"总结"小节：亮点 / 不足 / 改进措施
  - 待办清单侧重"改进措施"类可执行项
- **识别提示**：如输入结构为"好的/不好的/改进"三栏式，优先判定为复盘会

### 项目启动会 (Kickoff)
- **特征关键词**：启动、kickoff、目标、里程碑、分工、时间线
- **输出侧重**：项目目标 + 里程碑 + 角色分工 + 首次行动项
- **模板适配**：
  - 在"议题讨论"前增加"项目概况"小节（目标、范围、关键里程碑）
  - 角色分工可独立为表格
- **待办特征**：启动期首次行动项

## 类型判定优先级

当输入同时包含多种类型的特征时，按以下优先级判定：

1. 评审会（特征最鲜明，有明确的评审对象和通过/驳回结论）
2. 站会（按人/按天组织的进度汇报模式）
3. 复盘会（结构化回顾，有"好/不好/改进"框架）
4. 决策会（有明确的方案选择和决定）
5. 项目启动会（有目标和里程碑框架）
6. 同步会（进度汇报为主，无明确决策）
7. 头脑风暴（想法发散为主，无最终决定）
8. 一对一（仅两人，话题松散）

如确实无法判定，默认使用"同步会"模板，在备注中标注"会议类型待确认"。
