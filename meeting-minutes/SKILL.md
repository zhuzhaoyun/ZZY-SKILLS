# 会议纪要整理技能

将杂乱的会议输入（语音转文字、文字稿、笔记）整理为结构化的会议纪要，并保存到本地文件。

## 核心差异化能力

本技能不仅做格式整理，还提供以下通用 AI 做不到的能力：

| 能力 | 说明 |
|------|------|
| **隐式待办提取** | 不仅提取"明确指派"的事项，还识别"我回头看看"、"下周约一下"等隐性承诺为待办 |
| **不确定性标注** | 对听不清、有歧义、信息缺失的地方主动标注 🌀，不硬编 |
| **议题自动归并** | 将散乱的多轮对话按议题归组，而非按时间顺序平铺 |
| **会议类型感知** | 自动识别决策会/同步会/头脑风暴，使用对应模板结构 |
| **质量自查** | 输出前执行自检清单，确保完整性和可溯源性 |

## 输入类型与处理策略

| 输入类型 | 特征 | 处理策略 |
|----------|------|----------|
| **语音转文字稿** | 带时间戳、语气词多、重复、口语化严重 | 去除冗余（嗯、啊、这个那个）、修复断句、合并重复表述 |
| **文字稿（人工记录）** | 结构相对完整，可能有缩写、跳跃 | 梳理逻辑顺序，补充隐含的连接关系 |
| **笔记（要点式）** | 碎片化、关键词为主、缺少上下文 | 推理还原上下文，标记"推测"内容 |

## 边界情况处理

以下异常输入场景需特殊应对，不可静默失败：

| 场景 | 处理策略 |
|------|----------|
| **极短输入**（< 100 字，无明确议题结构） | 不强行拆分议题。使用简化模板：保留"基本信息"和"讨论要点"，将可提取内容归入一个议题，待办清单标注"原文信息量不足，以下为尽力提取结果"。输出长度相应缩减到 200~400 字 |
| **全英文输入** | 保持输入语言，整份纪要使用英文输出。模板结构不变，字段标签翻译为英文（如"议题讨论"→"Discussion Topics"、"待办清单"→"Action Items"）。🔄 符号保留，风险标注格式不变 |
| **多人同时发言/严重打断** | 在 `备注` 中标注"原文存在多处同时发言/打断，部分发言归属可能不准确"，对归属不确定的发言使用 🌀 标注 |
| **空输入/纯闲聊** | 不生成纪要文件。直接回复说明"输入内容无法整理为有效会议纪要"，并提示用户提供更完整的输入 |
| **仅含单一话题** | 不强行拆分为多议题。单独一个议题即可，省略编号（不用"议题一"） |
| **中英混杂输入** | 以主导语言（>50%）为输出语言。个别英文术语保留原样不翻译。在备注中说明 |
| **含敏感信息（薪资、人事等）** | 正常整理，但在纪要开头增加 `⚠️ 本纪要含敏感信息，请控制分发范围` 的警示行 |

如遇以上未列出的边界情况，遵循"诚实标注 > 硬编完善"原则处理。

## 工作流程

执行以下步骤，**不可跳过任何步骤**：

### Step 1: 预处理输入

1. 判断输入类型（录音转文字 / 文字稿 / 笔记），记入纪要的"原始输入"字段
2. 如为语音转文字稿：去除时间戳（保留时间范围）、语气词（嗯、啊、这个那个）、重复语句、打断重说；合并因断句导致的碎片短句
3. 如为笔记：保持原意，不做过度补充，对推测内容标注(?)或备注

### Step 2: 分析会议结构

1. **提取基础信息**：扫描全文寻找会议主题、时间、地点、参会人、主持人。缺失项在输出中保留字段但标注"待补充"
2. **会议名称推断**：如原始输入未提供明确主题，按以下优先级自动推断：(a) 原文首个议题的概括，(b) 出现频率最高的业务关键词（产品/项目/模块名），(c) 最高频动词+对象的组合（如"讨论发布计划"）。推断结果在纪要"备注"中标注"会议主题为自动推断，请确认"
3. **识别会议类型**：
   - **决策会**：特征——讨论了多个方案、做了选择/批准/否决、有明确的决定事项。输出侧重"决策依据 + 最终决定"
   - **同步会**：特征——各人汇报进展、更新状态、提出 blocker。输出侧重"当前状态 + 下步计划"
   - **头脑风暴**：特征——提出想法、讨论可能性、没有最终决定。输出侧重"想法列表 + 可行性初步判断"
   - 如果混合多种类型，以占主导的部分为准，在备注中说明

### Step 3: 议题归并与提炼

这是最关键的一步。不要按原文顺序平铺。

1. 通读全文，识别出独立的讨论主题/议题，每个议题赋予一个简明的标题
2. 将散落在不同发言中的相关内容归并到对应议题下
3. 对每个议题提炼出：
   - **讨论摘要**：谁说了什么关键观点（2-3 句话概括）
   - **结论/决议**：明确达成的共识或决定
   - **未解决问题**：有分歧、暂缓、待进一步讨论的事项
4. 对不确定的内容标注 🌀 并说明原因（"此处发言人未识别"、"此处听录不清"、"此处原文跳跃"）

### Step 4: 提取待办事项

分为**显式待办**和**隐式待办**两类，统一列入待办清单，在"来源"列标注提取方式。

**显式待办识别：** 明确指派的任务，如"张三你负责…"、"这件事交给李四…"

**隐式待办识别（这是核心差异化能力）：** 以下表述模式暗示存在待办事项：

| 表述模式 | 含义 | 待办生成 |
|----------|------|----------|
| "我回头看看/查一下/确认一下" | 隐式承诺 | 责任人=说话人，事项=查询/确认内容 |
| "下周/明天/回头约个时间" | 需要安排会议 | 责任人=提议人，事项=发起会议安排 |
| "发给我/发一份" | 需要发送资料 | 责任人=接收指令者，事项=发送指定资料 |
| "我跟进一下" | 隐式认领任务 | 责任人=说话人，事项=跟进指定事项 |
| "需要确认/核实" | 信息待确认 | 责任人=待确认（标注），事项=确认内容 |
| "要跟XX对齐/同步" | 需要跨部门协调 | 责任人=提议人，事项=与XX对齐/同步 |
| "尽快处理/尽快出方案" | 紧急待办 | 责任人=相关方，事项+截止时间=尽快 |
| "看看XX怎么说/问问XX的意见" | 需征询意见 | 责任人=提议人，事项=征询意见 |
| "帮我…" | 请求协助 | 责任人=被请求人，事项=协助内容 |

### Step 5: 识别风险与关注项

从讨论中提取需要关注的事项：
- **分歧点**：意见不一致但未解决的
- **阻塞项**：依赖其他团队/外部条件的
- **时间风险**：时间安排紧张或截止日期临近的
- **信息缺口**：缺少关键数据或信息无法做出决策的

### Step 6: 套用模板生成纪要

按照下方模板生成完整的会议纪要 Markdown 文件。

**纪要长度建议**：常规会议纪要控制在 500~1500 字。极短输入（< 100 字原文）控制在 200~400 字；大型决策会/评审会可放宽至 2000 字。宁可精炼也不冗长——纪要的价值在于"读完就能行动"，而非"事无巨细地还原"。

### Step 7: 质量自查

在保存前，逐一检查以下事项：

- [ ] 基础信息是否完整？（主题、时间、参会人）缺失项是否标注 "待补充"
- [ ] 每个议题是否有讨论摘要和结论/状态？
- [ ] 所有待办是否有责任人（或标注"待确认"）？
- [ ] 不确定的内容是否标注了 🌀？
- [ ] 是否存在原文有但纪要遗漏的重要信息？
- [ ] 待办清单中的"隐式待办"是否与原文一致，没有过度解读？

如有检查未通过，修正后再保存。

### Step 8: 保存到文件

1. 确定文件名：`会议纪要_YYYY-MM-DD_<简略主题>.md`
2. 保存到当前工作目录下的 `meeting-minutes/` 目录（如目录不存在则创建）
3. 使用 `Write` 工具写入完整文件
4. 告知用户文件保存路径及纪要概览（会议主题、类型、议题数、待办数）

## 参数说明

无固定参数。如有以下需求，请在执行前确认：
- 是否需要调整输出目录（默认 `meeting-minutes/`）
- 是否需要特别的额外关注点

## 质量验收标准

一份好的会议纪要应满足：
1. **完整性**：覆盖所有讨论的议题，不遗漏
2. **准确性**：结论和待办与原文一致，不曲解
3. **可追溯**：每个待办都可追溯到原文中的出处
4. **标注诚实**：不确定的地方如实标注，不硬编
5. **格式统一**：每次输出的模板结构一致
